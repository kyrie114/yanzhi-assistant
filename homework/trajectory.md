# FR-01 账户功能的开发轨迹

这张图记录一次编码代理完成真实功能的回路。菱形是回路的出口：假设不清就回到人，测试失败就只改失败的部分，验收有缺口就补测试。本次实际走过的路径用深色节点表示，没有发生的分支留在图上，因为下一次功能仍会经过它们。

```mermaid
flowchart TD
    A["人：指定一个真实功能<br/>完成标准是提交代码、补上测试、测试通过"] --> B["代理：阅读规格<br/>需求、验收、接口、模块和数据设计"]
    B --> C["代理：写明假设和成功标准<br/>本次选定 FR-01 账户"]
    C --> D{"假设是否挡住实现？"}
    D -->|是，需要人确认| C
    D -->|否| E["代理：按验收编写测试<br/>并写刚好能满足验收的实现"]
    E --> F["运行 go test 与 go vet"]
    F --> G{"通过？"}
    G -->|否| H["读失败信息<br/>只改导致失败的代码或依赖"]
    H --> F
    G -->|是| I["人：对照 AC-01-01 至 AC-01-07"]
    I --> J{"还有遗漏？"}
    J -->|是| E
    J -->|否| K["提交代码、测试和开发日志"]

    classDef human fill:#1F4E79,color:#fff,stroke:#1F4E79
    classDef agent fill:#0F6B4C,color:#fff,stroke:#0F6B4C
    classDef check fill:#F4A261,color:#1F2933,stroke:#C47A34
    class A,I,K human
    class B,C,E,F,H agent
    class D,G,J check
```

本次运行的记录：

1. 人给出作业：完成 1 个真实功能，提交代码，补测试，测试通过，并留下开发日志和轨迹图。
2. 代理读完 FR-01、AC-01 和接口第 4 节，选定账户注册、登录、退出、修改密码。
3. 假设没有挡住实现：账户先放在内存仓库；邮箱验证留到 FR-24；5 分钟登录压测不进入这次的单元测试。
4. 第一次 `go test` 时，最新的 `golang.org/x/crypto` 要求 Go 1.26，工具链被自动切换。测试本身通过。
5. 代理把 Go 钉在 1.22，把依赖钉在 jwt v5.2.2 和 crypto v0.31.0，再次测试通过。
6. 对照 AC-01-01 至 AC-01-07 后提交。AC-01-08 和 FR-24 明确留在图外。
