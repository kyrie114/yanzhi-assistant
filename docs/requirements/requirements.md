## 1 引言

### 1.1 目的

本文说明研智助手首期要解决的问题、使用者要完成的事情，以及由此确定的系统能力、质量要求和约束。评审、设计和测试以本文为准。

### 1.2 读者

产品负责人、设计、开发、测试和部署人员。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| 知识库 | 用户创建的一组资料及其索引、图谱和主题页。一个用户可以有多个知识库 |
| 资料 | 知识库中的一份文件、网页或手工录入的文本。入库后有独立的处理状态 |
| 切块 | 资料解析后的检索单元，带有所属资料和位置。子块用于命中细节，父块保留更大的上下文 |
| 直接问答 | 围绕选定资料做一次检索并生成回答。回答中的事实须能回到切块 |
| 深度查阅 | 同一问题下多次检索、阅读和整理。过程分步可见，可以停止 |
| 知识图谱 | 从资料中抽出的实体、关系，以及每条关系对应的原文位置 |
| Wiki | 由资料整理出的主题页。页与页之间有链接，页内注明来源 |
| FAQ | 用户维护的标准问、相似问法、不应命中的问法和答案 |
| docreader | 负责把文件和网页转成文本与页面图片的解析服务 |
| 主服务 | 对浏览器提供接口的服务，负责账号、任务、索引、检索、问答和图谱 |

## 2 背景与目标

研究生和科研人员的论文、笔记、网页和实验记录分散在本地文件夹里。需要引用时，往往要重新打开原文核对页码；读过的概念关系也留不下来，下一次还是从文件名里翻。

研智助手提供个人知识库。使用者把资料放进来，按自己的题目整理，基于这些资料提问并核对原文，并把反复出现的概念沉淀成图谱和主题页。

| 编号 | 目标 | 首期是否必须看到结果 |
| --- | --- | --- |
| G1 | 资料能入库、能检索，回答能回到原文位置 | 是 |
| G2 | 读过的内容能沉淀成图谱和可浏览的主题，而不是只留在一次对话里 | 图谱是；主题页在随后迭代完成 |
| G3 | 个人资料边界清楚，系统能部署，出了问题能按一次请求追查 | 是 |

## 3 使用者与场景

### 3.1 使用者

| 使用者 | 说明 | 账号从哪来 |
| --- | --- | --- |
| 注册用户 | 管理自己的知识库，进行问答、查阅和知识整理 | 自行注册 |
| 系统管理员 | 配置模型连接、查看运行日志、保证服务可用。不代替用户阅读资料 | 部署时由命令行创建 |

### 3.2 场景

**场景 A 入库。** 用户新建知识库「论文阅读」，上传一组 PDF，给其中几篇打上「检索」标签。他需要看到每一篇是待处理、处理中、已完成还是失败；失败时能看到原因并重试。

**场景 B 核对。** 写某一节之前，用户把提问范围限定在这个标签里，问某篇论文用了什么数据集。回答里的每一条事实都能点开，看到标题和物理页码，以及对应的原文片段。

**场景 C 顺着关系找。** 用户想知道某个方法还在哪些已入库论文里出现、连着哪些数据集。他打开图谱，从方法节点走到论文和数据集，再点回原文页。

**场景 D 沉淀。** 同一组概念在多篇论文里反复出现。用户希望系统整理出若干互相链接的主题页，自己也可以改一版并留下历史。固定不变的事项，例如实验室服务器地址，则记成 FAQ，以后直接答对，不必假装来自某一页论文。

**场景 E 一次看不完的问题。** 用户要比较三篇论文的实验设置。一次检索不够，他发起深度查阅，能看见系统正在检索、阅读和整理，也可以中途停掉。

## 4 用户需求

优先级与后文功能需求一致：必须（首期发布）、应该（紧随其后的迭代）、可以（有余力时做）。

| 编号 | 用户需要完成的事 | 优先级 | 对应目标 |
| --- | --- | --- | --- |
| UR-01 | 注册并登录，只有自己能进入自己的空间；离开某台设备或修改密码后，相应的登录状态失效 | 必须 | G3 |
| UR-02 | 建立多个知识库，把论文放进去，并维护标题、作者、年份等书目信息 | 必须 | G1 |
| UR-03 | 知道每份资料处理到哪一步，失败时能重试 | 必须 | G1 |
| UR-04 | 用标签整理资料，提问和浏览时能限定在某个知识库或标签 | 必须 | G1 |
| UR-05 | 针对自己的资料提问，回答中的事实能回到具体位置；库里没有依据时不要编造出处 | 必须 | G1 |
| UR-06 | 从已入库资料中看到方法、数据集、指标和论文之间的关系，并沿关系找到原文 | 必须 | G2 |
| UR-07 | 运维人员能更换对话、向量、重排和视觉模型，用户侧密钥不可见 | 必须 | G3 |

| UR-09 | 保留问答记录，并在同一话题里继续追问 | 应该 | G1 |
| UR-10 | 追问时系统先把指代补全，再去资料里找 | 应该 | G1 |
| UR-11 | 更贴题的片段排在前面 | 应该 | G1 |
| UR-12 | 命中某一句时还能看到它所在的段落；冷门说法也能被问到 | 应该 | G1 |
| UR-13 | 不同知识库可以用不同的回答口径，打开资料时能看到可以问的问题 | 应该 | G1 |
| UR-14 | 比较或串起多份资料时，分几步查阅，过程可见，也可以停 | 应该 | G1、G2 |
| UR-15 | 知识库里没有材料时，可以另外查公开网页，并和库内出处分开 | 应该 | G1 |
| UR-16 | 把多篇资料整理成可浏览、可修改的主题页，页上保留来源 | 应该 | G2 |
| UR-17 | 为重复出现的问题保存标准答案，并避免被不相关的问法误触发 | 应该 | G2 |
| UR-18 | 改正切错的段落，使后续问答和图谱使用改正后的文本 | 应该 | G1 |
| UR-19 | 把选中的文献导出为可粘贴的参考文献 | 应该 | G1 |
| UR-20 | 为一篇文献留下带来源的阅读要点，并保留改过的版本 | 应该 | G2 |
| UR-21 | 论文以外的 Word、网页、笔记和整个文件夹也能入库 | 应该 | G1 |
| UR-22 | 扫描件、表格、图和录音里的信息也能被问到 | 应该 | G1 |
| UR-23 | 出了问题能按一次请求查看处理过程，日志里没有资料全文和密钥 | 应该 | G3 |

## 5 功能需求

每条功能需求都来自上一节的用户需求。优先级取自对应的用户需求。

### FR-01 账户

- 来源：UR-01
- 优先级：必须
- 说明：用户使用邮箱、姓名和密码注册。邮箱全局唯一。密码至少 8 位，且同时包含字母和数字。注册成功后可以登录，登录签发的访问令牌有效期 2 小时。退出登录只使当前这枚令牌失效，同一用户其他未过期令牌仍然有效。修改密码必须校验旧密码，新密码满足同样的规则；修改成功后，该用户已经签发且尚未过期的令牌全部失效。登录失败时，不存在的邮箱和错误密码使用同一句提示。

### FR-02 资料访问

- 来源：UR-08
- 优先级：必须
- 说明：知识库、资料、切块、笔记、会话、标签、图谱、Wiki 和 FAQ 属于创建它们的用户。其他用户访问这些资源时返回 404，响应不区分「不存在」和「不属于你」。系统管理员访问这些资源的详情、原文和图谱时同样返回 404。未登录或令牌失效返回 401。非管理员调用模型配置接口返回 403。原始文件只能通过鉴权后的下载接口获取。检索在查询条件中限定为当前用户的资料，而不是先查出再过滤。

### FR-03 知识库与资料

- 来源：UR-02
- 优先级：必须
- 说明：用户可创建多个知识库，名称不能为空且不超过 50 个字符。向知识库上传 PDF 时，可填写并在之后修改标题、作者、年份和出处。列表支持分页和按标题搜索。删除资料时，同时删除原始文件、切块和向量；图谱按 FR-07 清理。设置了打开密码的 PDF 在上传时返回 422，提示「文件已加密，无法解析」，不创建资料、不进入处理队列。页数检查只对没有打开密码且能读出页数的文件执行。同一用户再次上传 SHA-256 相同的文件时：原记录为失败则不新建记录，把该记录重新置为待处理；原记录为待处理、解析中、向量化中或已完成时返回 409，并给出已有资料的位置。不同版本的识别见 OQ-02。PDF 上传接口不接受其他格式，其他格式见 FR-21。

### FR-04 解析与索引

- 来源：UR-03、UR-05
- 优先级：必须
- 说明：上传成功后，主服务创建处理任务，状态按「待处理 → 解析中 → 向量化中 → 已完成 / 失败」流转。解析阶段通过 gRPC 调用 docreader，取回按物理页组织的文本。物理页码从 1 开始，不使用期刊印刷页码。docreader 不可用，或单次调用超过 120 秒没有返回时，任务失败，原因为「文档解析服务暂不可用」，不生成切块。全篇没有可用文本时按 FR-22 处理。只有部分页能抽出文本时，这些页正常切块，抽不出文本的物理页在详情中列出，整篇仍可完成，后续页码不重排。切块在主服务完成，默认 500～800 字符，相邻块重叠 100 字符，参数可配置。每个切块记录资料 ID、起始物理页码和段落序号。问答出处不展示段落序号。主服务调用向量模型并写入 PostgreSQL。向量服务持续失败时自动重试 2 次，然后标记失败，用户可手动重试，同一资料最多 3 次。服务重启后，停在解析中或向量化中的任务标记为失败，原因为「处理中断，请重试」，这次失败不计入 3 次手动重试。资料变为已完成后，另行开始 FR-07 的图谱抽取；抽取失败不把资料改回失败。

### FR-05 标签与范围

- 来源：UR-04
- 优先级：必须
- 说明：用户可在自己的知识库中创建、重命名和删除标签。一份资料可以属于多个标签。资料列表、直接问答、深度查阅和图谱都可以限定到一个知识库、一组标签或若干份资料。删除标签不删除资料。其他用户不能读取这些标签。

### FR-06 直接问答

- 来源：UR-05
- 优先级：必须
- 说明：用户在选定范围内提问。系统只检索当前用户名下、状态为已完成的切块，默认取 5 条。检索同时走向量和关键词，两路结果融合后再交给对话模型。图谱补充见 FR-07，重排见 FR-11，父子块和预生成问题见 FR-12。待处理、解析中、向量化中和失败的资料不参与检索。回答以流式方式返回，语言与问题一致；判断不了时用简体中文。出处格式为「资料标题, 第 X 页」，X 是物理页码，切块跨页时取起始页。点击出处展示命中的切块，标题使用书目中的标题。最高相似度低于阈值，或片段不足以支持结论时，回复「知识库中未找到相关依据」，不生成出处。阈值见 OQ-08。知识库中没有已完成资料时，输入不可用，并提示先完成入库。寒暄和不需要资料的短句不检索、不附出处。资料正文中的指令语句不改变上述规则，也不得因此输出系统提示词。模型不可用时提示稍后重试，并给出本次 request_id，不展示内部堆栈。

### FR-07 知识图谱

- 来源：UR-06
- 优先级：必须
- 说明：资料状态变为已完成且所属知识库启用图谱后，主服务创建抽取任务，状态按「待抽取 → 抽取中 → 已完成 / 失败」流转。20 页以内的文本型 PDF，在模型服务正常时，抽取在资料完成后 3 分钟内结束。实体类型为：文献、作者、方法、数据集、指标、研究问题。关系类型为：作者属于文献、文献提出方法、使用数据集、报告指标、针对研究问题、对比、文献引用文献。每条关系至少有一处证据，包含资料 ID、切块 ID 和物理页码；没有证据的关系不保存。同一用户内，去掉首尾空白并合并连续空白后名称相同的实体合并为一个，拉丁字母不区分大小写。不同用户的节点互不可见，也不合并。引用只连接到该用户库内已完成、且标题能够对应的资料；对不上的题名记在该资料的未入库引用中，不建成可打开的资料节点。界面提供单篇资料的一跳邻居，以及按知识库或标签过滤的图谱。点击节点可见名称、类型和来源页，点击边可见关系类型和证据句。删除资料时，删除只以该资料为证据的关系，以及因此不再连接任何关系、且不是仍留在库中的文献节点。直接问答在已有图谱时，可从本次命中的实体沿一跳取最多 3 个额外切块，这些切块必须属于同一用户的已完成资料，并标为「图谱补充」。回答中的出处仍然只能来自这次实际交给模型的切块。图谱为空或抽取失败时，问答仍按 FR-06 进行。抽取调用持续失败时自动重试 2 次，然后标记失败；用户可手动重试，最多 3 次。服务重启后，停在抽取中的任务标记为失败，不一直保持抽取中。正文中的指令不改变节点名称，也不替代证据。实体和关系存在 PostgreSQL 中。类型清单的调整见 OQ-11。

### FR-08 模型连接

- 来源：UR-07
- 优先级：必须
- 说明：系统管理员配置对话、向量、重排和视觉模型的地址、名称和密钥，保存前可测试连接。密钥加密存储，界面和接口只显示末 4 位。普通用户不能打开该配置。尚未配置对话模型时，问答、要点和深度查阅提示联系管理员，不返回 500。已经存在向量时，更换向量模型或向量维度必须经过确认；确认后已有资料回到待处理，旧向量不再参与检索，原图谱不参与补充，待资料再次完成后重新抽取。未确认则配置保持不变。密钥由谁持有见 OQ-01。

### FR-09 会话

- 来源：UR-09
- 优先级：应该
- 说明：系统保存每次提问、回答和出处。用户可查看、重命名和删除自己的会话。同一会话中的追问携带最近 5 轮上下文。其他用户访问该会话返回 404。

### FR-10 查询改写

- 来源：UR-10
- 优先级：应该
- 说明：多轮追问在检索前改写成一句自洽的查询，再执行 FR-06。改写失败时使用原问题，问答不因此失败。日志只记录是否改写。是否保存正文见 OQ-09。

### FR-11 重排

- 来源：UR-11
- 优先级：应该
- 说明：混合检索得到候选后，若已配置重排模型，则按相关度重排再取前若干条交给生成。未配置时沿用融合后的顺序，问答仍然可用。图谱补充发生在取定这些条目之后，不占用该名额。重排模型的密钥按 FR-08 保存。

### FR-12 切块上下文与问法

- 来源：UR-12
- 优先级：应该
- 说明：索引时为切块保留父块。父块是包含该切块的更大文本，约 2000～3000 字符，参数可配置。命中子块时，生成前可以读到父块；出处页码仍以子块起始页为准，父块不单独占一条出处。系统可为每个切块生成不超过 3 个可能的问法，并与该切块一起参与检索。生成失败时，原文检索不受影响。

### FR-13 知识库回答设置与推荐问题

- 来源：UR-13
- 优先级：应该
- 说明：每个知识库可设置回答说明和检索阈值。说明只影响该库被选中时的回答方式，不改变出处规则。未单独设置时使用系统默认。打开一份已完成的资料或一个知识库时，展示不超过 5 个根据该范围生成的推荐问题；用户点击后填入提问框。其他用户看不到这些内容。

### FR-14 深度查阅

- 来源：UR-14
- 优先级：应该
- 说明：用户可对选定范围发起深度查阅。界面按顺序展示检索资料、阅读片段、查看图谱、查看主题页和整理回答等已发生的步骤。默认最多 8 步，达到上限后用已获得的材料给出回答，并说明查阅结束，不再调用工具。用户可停止，停止后 5 秒内不再发起新的模型调用。可使用的动作限于：检索本人知识库、按资料阅读切块、列出资料、查询本人图谱、检索并阅读本人 Wiki、查看已导入表格的列说明。这些动作不能返回其他用户的数据。某一步持续失败时，任务标为失败并保留已完成步骤的结果；再次查阅是一次新任务。正文和页面中的指令不能让这些动作越过资料边界。

### FR-15 公开网页

- 来源：UR-15
- 优先级：应该
- 说明：用户可在一次提问中打开公开网页检索。知识库没有足够依据时，回答可以引用网页标题，并与库内出处分列。网页不写成库内页码。用户关闭该选项后，行为回到 FR-06。系统不登录需要账号的网站，也不绕过网站的访问控制。

### FR-16 Wiki

- 来源：UR-16
- 优先级：应该
- 说明：用户可让一个知识库生成 Wiki：若干主题页，页间有链接，每页注明来源资料和物理页码。生成是异步的，失败不影响资料本身和直接问答。所有者可修改页面，每次保存保留上一版，并可恢复。其他用户不能读取或保存这些页面。深度查阅阅读 Wiki 时使用同一批页面。

### FR-17 FAQ

- 来源：UR-17
- 优先级：应该
- 说明：用户可在知识库中维护 FAQ，包含标准问、答案、若干相似问法和若干不应命中的问法。提问与标准问或相似问法足够接近、且不落在不应命中的问法上时，直接返回该答案，并标明来自 FAQ，不附论文页码。删除后不再命中。其他用户不能读取这些条目。

### FR-18 切块修订

- 来源：UR-18
- 优先级：应该
- 说明：资料所有者可查看切块并修改文本。保存后该切块重新生成向量和关键词索引，物理页码不变，旧文本保留为可回看的版本。以该切块为证据的图谱关系立即停止参与补充，并触发该资料重新抽取；新的关系在抽取完成且证据与新文本一致后才恢复补充。其他用户调用修改接口返回 404。

### FR-19 参考文献导出

- 来源：UR-19
- 优先级：应该
- 说明：根据书目信息生成 BibTeX 和 GB/T 7714 条目。版本见 OQ-07；决定之前按 GB/T 7714-2025，格式做成可替换的模板。缺少必需字段时列出缺失项，不猜测补全，其余完整的文献照常导出。支持多篇导出为一个文件，引用键互不重复。

### FR-20 阅读要点

- 来源：UR-20
- 优先级：应该
- 说明：对一份已完成的资料生成阅读要点，包含研究问题、方法、实验设置、主要结论、局限性。每个小节至少有一处能对应到该资料切块和物理页码的出处；对不上的标记不写入笔记。资料未完成时不能生成。超出模型上下文的长文分段处理后合并。保存后可重新生成，上一版保留。正文中的指令不能去掉出处，也不能引出系统提示词。

### FR-21 多种资料来源

- 来源：UR-21
- 优先级：应该
- 说明：除 PDF 外，用户可上传 docx、pptx、xlsx、csv、epub、html、md、txt 和常见图片，提交一个 http(s) 地址，或在页面上录入一段文本。也可以一次选择一个文件夹，服务端保留相对路径。这些输入交给 docreader；网页只提取正文，不执行页面脚本。主服务拿到文本后，走与 PDF 相同的切块、索引、问答和图谱。单文件仍受第 6 节的大小限制。网页抓取失败时记录原因，不保存整站。没有物理页码的资料，出处用「第 1 页」，详情中说明该资料没有 PDF 页码。手工录入的文本按一份资料处理。

### FR-22 扫描件、表格、图片与录音

- 来源：UR-22
- 优先级：应该
- 说明：docreader 标出没有可用文本层的页面并交出图片。主服务调用已配置的视觉或文字识别模型，按物理页码写回切块。docreader 不调用模型。识别未配置、超时或结果为空时，该资料失败，原因写明识别未成功，不生成空切块。部分页已有文本时，仍只列出无文本页，不强制整篇识别。表格转为可检索的文本，保留单元格内容。图片由 docreader 抽出，主服务生成文字描述后索引；描述失败时跳过该图，资料其余部分仍可完成。用户可上传录音，转写文本后按一份资料索引。转写失败时该录音标记失败，不影响其他资料。上述切块可以作为图谱证据。识别引擎的选型见 OQ-03。

### FR-23 运行日志

- 来源：UR-23
- 优先级：应该
- 说明：主服务记录请求、资料处理、图谱抽取、深度查阅和模型调用。模型调用记录包含 request_id、用户 ID、模型名称、耗时、输入与输出 token 数、结果状态。管理员可按时间、用户和类型筛选，每页 50 条。用户可查看自己的处理步骤和查阅步骤，看不到资料全文。日志为 JSON，同一次请求使用同一个 request_id。日志中不出现明文密码、明文密钥、提示词正文、回答正文和资料全文。是否临时记录正文见 OQ-09。

### FR-24 邮箱与密码重置

- 来源：UR-24
- 优先级：应该
- 说明：注册成功后向该邮箱发送 24 小时内有效的验证链接。未验证时可以登录并看到提示，但不能上传或提问。已验证用户可申请重置密码，链接 30 分钟内有效且只用一次。新密码满足 FR-01。重置成功后，该用户已签发的令牌失效。邮件发送失败时给出明确提示，不另建账号。

### FR-25 回答反馈

- 来源：UR-25
- 优先级：可以
- 说明：用户可对一次回答点赞或点踩。点踩时可选择出处错误、答非所问、内容不完整、关系错误或其他。同一回答只保留最新一条反馈。管理员可导出按日期汇总的数量，导出文件不含问题和回答正文。

### FR-26 受信任的外部检索

- 来源：UR-26
- 优先级：可以
- 说明：用户可创建一把只用于检索自己知识库的密钥，并随时作废。使用该密钥的调用只能检索这名用户的已完成资料，不能读取其他用户的切块，也不能调用模型配置或下载管理接口。

### FR-27 来源同步

- 来源：UR-27
- 优先级：可以
- 说明：用户可添加一个网页地址或 RSS，系统按不超过每天一次的频率检查新内容。新内容走 FR-21 的入库过程。需要登录才能阅读的地址记为失败，不把登录页保存成资料。

### FR-28 使用偏好

- 来源：UR-28
- 优先级：可以

## 7 约束

- C-01 运行结构。系统分为三个进程。前端使用 Vue 3 和 TypeScript，生产环境由 Nginx 提供页面，并将 `/api` 转发到主服务。主服务使用 Go，对浏览器提供 HTTP 接口，负责任务、切块、向量、检索、问答、图谱编排和模型调用。docreader 使用 Python，通过 gRPC 把 PDF、Office、网页、Markdown、图片和录音转成文本或页面图片；它不连接业务数据库，不生成向量，不回答问题，不抽取图谱。扫描页和图片的识别由主服务调用已配置的模型完成。
- C-02 数据存放。业务数据和向量放在 PostgreSQL。图谱使用 PostgreSQL 中的表，不另外部署图数据库。原始文件放在主服务可访问的目录中，下载必须经过鉴权。处理任务记在数据库中，由主服务的 worker 领取。
- C-03 模型。对话、向量、重排和视觉能力通过可配置的 HTTP 接口调用。费用在开发和演示期间由项目组承担，需要控制调用次数。
- C-04 交付形态。本期交付 Web 应用和 Docker Compose 部署。不包含桌面安装包，也不包含多活集群。
- C-05 时间。业务时间使用 Asia/Shanghai。界面上的处理时间和日志时间标明北京时间。
- C-06 文件处理。上传文件中的脚本不执行。网页导入不执行页面脚本。
